# AI 적용 시험

ux-baseline 패키지만 받은 AI 에이전트가 실제 화면을 만들 때 검사기를 통과하는지, 위반을 받고 고치는지 확인한다.
자기 보고("지켰다")가 아니라 검사기 결과로 채점한다.

## 도구

| 파일 | 하는 일 |
|---|---|
| `grade.mjs <디렉터리>` | 결과물(`index.html` + CSS)을 채점: stylelint·html-validate(lint/ 설정), 실제 Chromium 에서 axe-core(색 대비 포함), 320px 리플로, Tab 초점 표시. 위반을 `lint/rule-map.yaml` 로 룰 ID 에 대응 |
| `grade-all.mjs <디렉터리...>` | 여러 결과물을 채점해 표로 요약 |
| `check-components.mjs [id,...]` | 컴포넌트 규격(components/)을 실제 브라우저에서 같은 방식으로 검사 — CI `browser-check` 작업 |
| `tasks/` | 시험 과제 |

```sh
cd lint && npm ci && cd ../trials && npm ci
node check-components.mjs            # Chromium 이 없으면: npx playwright-core install chromium
node grade.mjs <결과물 디렉터리>
```

## 2026-10-18 시험 (`runs/2026-10-18/`)

**방법**
- 과제 3개: T1 민원 신청 폼(오류 상태 포함), T2 공지사항 목록(검색·표·페이지네이션), T3 삭제 확인 대화상자·결과 알림·탭.
- 조건 A: 작업 디렉터리에 `CLAUDE.md`(= dist/core.md), 스킬 `ux-baseline/`, `tokens.css` 만 준다.
- 조건 B(기준선): `tokens.css` 와 "토큰을 쓰고 WCAG 2.2 AA·KWCAG·한국어 사용성을 지켜라"는 지시만 준다.
- 에이전트는 작업 디렉터리 밖을 읽지 않고, 검사기 없이 1회차를 만든다. 2회차는 채점 보고서(CHECK-REPORT.md)를 받고 고친다.
- 두 회차 모두 마지막 검사기 설정으로 다시 채점했다(시험 중 검사기 오탐을 고쳤기 때문).

**결과 — 검사기 오류 수**

| 과제 | A 1회차 | B 1회차 | A 2회차 | B 2회차 |
|---|---|---|---|---|
| T1 신청 폼 | 2 | 2 | 0 | 0 |
| T2 공지 목록 | 4 | 5 | 0 | 0 |
| T3 삭제 대화상자 | 1 | 1 (+경고 1) | 0 | 1 |
| 합계 | 7 | 8 | 0 | 1 |

자동 검사로는 보이지 않는 룰 몇 개를 따로 확인했다: 날짜 표기(COPY-056 `2026. 10. 16.`)는 A 15/15, B 4/14(T2-B 는 10건 모두 `2026-10-16`).

**해석**
1. 검사기 오류 수만 보면 패키지 유무의 차이가 작다. 강한 모델은 일반적인 접근성 지시만으로도 기본기를 지킨다.
2. 차이를 만든 것은 **검사기 + 고침 루프**다. 보고서를 받은 뒤 6개 중 5개가 오류 0이 됐다(남은 1개는 B 의 위험 버튼 색 대비).
3. 패키지가 더하는 것은 이 체계가 정한 결정들(날짜 표기, 필수 표시 한 방식, 오류 요약 위치, KWCAG 7.2.1 등)과 규격 재사용에 따른 일관성이다. 이 중 상당수는 아직 자동 검사가 없어 오류 수에 나타나지 않는다 — 다음 작업은 이런 체계 결정을 검사기로 옮기는 것이다.
4. A 의 1회차 오류 대부분은 **패키지 자체의 결함**에서 왔다. 시험에서 찾아 고친 것:
   - 기본 스타일 없음 → `tokens/base.css` 신설(box-sizing 등). 이것이 없어 컴포넌트 규격 12개가 320px 에서 넘쳤다(jsdom 검사로는 못 찾음 → 실제 브라우저 검사 `check-components.mjs` 추가, CI 반영)
   - 페이지네이션 규격의 `aria-label="N페이지"` 가 axe label-content-name-mismatch 위반, 좁은 화면에서 넘침
   - `--color-link-default`(primary-50)를 회색 표면에 쓰면 4.16:1 — 캐러셀·도움 패널 규격 수정
   - 오류 요약 규격이 없어 AI 가 역할 없는 div 에 aria-labelledby 를 씀 → `components/error-summary` 신설
   - 강제 색상 모드의 시스템 색(Highlight 등)을 토큰 규칙이 막아 AI 가 접근성 보강 코드를 지움 → CF-064 로 허용
   - html-validate 의 표기 취향 규칙(doctype 대소문자 등)이 룰과 무관한 오류를 냄 → 끔
   - 휴대전화 `autocomplete="tel-national"`(type=tel 에는 쓸 수 없음)을 A·B 모두 씀 → text-field 규격에 `tel` 명시

## 2026-10-18 시험 2 — 스크립트가 있는 화면 (`runs/2026-10-18-t4/`)

채점기에 실제 키 입력으로 확인하는 동작 검사를 더했다: 대화상자(열면 초점이 안으로, 모달은 Tab 이 안에 머묾, Esc 로 닫히고 초점이 여는 버튼으로), 탭(→ 키로 다음 탭), 디스클로저·아코디언(Enter 로 펼침·접음). 체계 결정 검사(html-validate 자체 규칙: 날짜 표기, 필수 표시 방식, 오류 요약 위치·제목, 대화상자 버튼 문구)도 이때부터 들어갔다.

과제 T4: 알림 설정 화면(탭 3개, 스위치, 복수 선택, 자주 묻는 질문 펼침, 해지 확인 대화상자, 결과 알림)을 바닐라 JS 로.

| 조건 | 1회차 오류 | 경고 |
|---|---|---|
| A (패키지, 시험 1 뒤 고친 판) | 0 | 0 |
| B (토큰 + 일반 접근성 지시) | 3 | 1 |

- 두 조건 모두 동작 검사(대화상자·탭·펼침)는 통과했다. B 의 오류는 토큰이 아닌 값 직접 사용과 `main:focus` 의 outline 제거(A11Y-016).
- 이후 B 의 `transition-duration: 0s`(동작 줄이기) 지적이 오탐임을 찾아 고쳤다 — MOTION-010 측정 기준이 0s 를 허용한다. 지금 검사기로는 B 오류 2.
- 보관된 결과물에는 tokens.css·base.css 가 없다. 다시 채점하려면 tokens/ 에서 복사한다(grade.mjs 가 경고한다).
- A 는 과제의 "스위치 + 저장 버튼" 대신 FORM-041(저장 버튼이 있으면 스위치 대신 체크박스)에 따라 체크박스를 썼다 — 패키지가 과제 문구보다 체계 결정을 앞세운 사례.
- 시험 1 뒤 고친 패키지(base.css, 규격 수정)에서 A 의 1회차 오류가 7 → 0 으로 줄었다. 과제가 달라 직접 비교는 아니다.

## 2026-10-18 독립 검토

룰과 결정(CF-001~064)을 만들지 않은 별도 에이전트 4개가 원문(KWCAG 2.2 docx, KRDS PDF, AI 투명성 가이드라인, WCAG Understanding)과 대조했다.
원문과 다른 오류 7건(코치마크가 시간 제한 경고를 막음, 지워지지 않은 예외, KWCAG 자동 재생 3초 예외 누락, 시간 제한 예외의 고지 의무 누락, EU AI Act 조항 번호, 번쩍임 50회 상한, 딥페이크 표시 범위)과 경고 약 40건이 나왔고 모두 반영했다. 우선순위 분류가 틀렸던 CF 4건(원칙 1 → 2·3)도 바로잡았다.

반영 결과를 다시 별도 에이전트가 재검증해 17건(반영이 불완전하거나 룰·규격·예시가 서로 어긋난 곳)을 더 찾았고 모두 고쳤다.
같은 종류의 결함이 다시 들어오지 않도록 검사기를 더했다: 확정 룰 예시의 CSS 변수가 토큰이거나 예시 안에서 선언됐는지(`validate.py`), 컴포넌트 규격 본문이 언급한 룰 ID 가 `rules` 목록에 있는지(경고).

## 2026-10-18 시험 3 — 도입 꾸러미만 받은 에이전트 (`runs/2026-10-18-t5/`)

방법: 빈 프로젝트에 `npm i -D ux-baseline`(pack 한 .tgz) → `npx ux-baseline init` 만 해 두고, 이 저장소를 모르는 에이전트에게 과제 T5(AI 문서 요약 화면: 스트리밍·중단·출처·확신 낮음·다시 생성·고치기·복사·서비스 오류와 답 없음 구분)를 줬다. 검사하라는 말은 하지 않았다.

**결과**
- 에이전트는 AGENTS.md 의 지침만 보고 Chromium 을 설치하고 `npx ux-baseline check` 를 돌려 오류 0 / 경고 0 으로 마쳤고, 보고에 마지막 검사 줄을 그대로 적었다.
- 스스로 "check 는 처음 연 상태만 본다"는 한계를 찾아 상태 7개(입력 오류·생성 중·중단·완료·고치기·서비스 오류·답 없음)를 따로 검사했다 → **`states` 설정으로 꾸러미에 넣었다.** 같은 7개 상태를 독립 설정으로 다시 검사: 오류 0.
- 상태 검사를 넣다가 찾은 검사기 결함: 마우스 단계 뒤 :focus-visible 이 꺼져 모든 요소를 초점 표시 없음으로 오탐 → 수정.
- 자동 검사로 판정되지 않는 룰을 별도 에이전트가 원문 측정 기준으로 검토(AI·STATE·COPY·FORM 51개 룰):
  - 위반 5건: COPY-001(MUST, "밑줄 친 부분" — 감각 특성만으로 대상 지정), STATE-002(SHOULD, 1초 안에 끝나도 스피너 표시), STATE-032(SHOULD, 입력 중 이탈 확인 없음), COPY-055(SHOULD, 한 문장 두 행동), FORM-033(MAY)
  - AI 룰(AI-001~012, 015)은 모두 통과 — 중단·재생성·출처·오류와 답 없음 구분이 기준대로 구현됐다
  - 측정 기준이 모호해 판정이 갈린 룰 12개(AI-011·007·006·003, STATE-021·019·014, FORM-033·012, COPY-055·027·010) — 다음 작업에서 측정 기준을 고친다

## 2026-10-18 시험 4 — 다른 화면·다른 모델 (`runs/2026-10-18-t6/`, `runs/2026-10-18-t7/`)

방법: 시험 3과 같다(꾸러미만 설치된 빈 프로젝트, 검사하라는 말 없음). 모델은 Claude Sonnet, 과제는 T6 회원가입·T7 운영 대시보드.

**결과**
- 두 에이전트 모두 AGENTS.md 만 보고 `check` 를 돌리고 `states` 에 상태를 스스로 등록했다(T6 6개, T7 10개). 1회차 지적(T6: outline 제거·이탈 확인 없음, T7: p-as-heading·페이지 링크 이름·320px 넘침)을 고쳐 오류 0 / 경고 0 으로 마쳤다.
- T6 에이전트는 v0.2 에 넣은 STATE-032(입력 중 이탈 확인) 경고를 받고 beforeunload 를 넣었다 — 새 검사가 실제로 동작을 바꾼 사례.
- T6 에서 에이전트가 FORM-032(가나다순)와 FORM-024(동의 선택지 순서) 사이를 주석으로 판단한 것을 찾아 **CF-066** 으로 해석을 고정했다. 처음에는 에이전트 판단대로 '동의함' 먼저로 정했다가, 2차 검토에서 가나다순('동의하지 않음' → '동의함')이 KRDS 예시 화면과 같다는 것을 찾아 정정했다 — 시험 에이전트의 판단도 검증 대상이라는 사례. T7 에서 시각에 따라 달라지는 상태를 states 로 재현하지 못한 한계를 찾아 **states 의 page 에 쿼리**를 허용했다.
- 자동 검사 밖 룰 독립 검토(T6 57개, T7 58개 룰):
  - T6 위반 5건(SHOULD): 스크립트가 만든 오류 요약 위치(FORM-077), 날짜 오류 링크 대상(FORM-078), 입력 칸 너비(FORM-056), 목록 어미(COPY-027), 한 문장 두 행동(COPY-055)
  - T7 위반 9건(MUST 3): 좋음·나쁨을 색으로만 구분(COLOR-001), 기호 없앤 목록에 role="list" 없음(A11Y-007), '옆의 표'(COPY-001) / SHOULD: 배지 nowrap 상속, 버튼 그룹 크기, 본문 폭, 15px 보조 글자, JS 가 만든 날짜의 time 요소 / MAY 1
- 검토 결과로 검사기를 고쳤다: **states 의 렌더된 DOM 에도 html-validate**(FORM-077·COPY-056 류를 잡음), **계산 스타일 검사 3개**(list-role·badge-nowrap·button-group-equal), 감각 표현 대상에 표·그래프·그림 추가. 이 검사로 컴포넌트 규격 8개와 시험 2의 '좋은 화면' 픽스처에도 role="list" 누락이 있음을 찾아 고쳤다.
- 측정 기준이 모호한 룰 15개(T6 6, T7 9)를 2차로 정비했다(아래 변경 기록).
- 남은 수동 확인: 색만으로 좋음·나쁨 구분(COLOR-001) 같은 의미 판단은 자동화하지 않았다.
