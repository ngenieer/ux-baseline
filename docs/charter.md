# ux-baseline 프로젝트 지침 (원문 사본)

claude.ai 프로젝트 "웹프로젝트 를 위한 UI/UX"의 지침을 옮겨 둔 것이다. 룰의 출처 `UXB_CHARTER`가 이 파일을 가리킨다.
지침이 바뀌면 이 파일도 함께 고친다.

## 프로젝트 목적
어느 웹프로젝트에도 적용할 수 있는 UI/UX 룰을 수집·정리하고, 룰끼리 충돌하지 않는 하나의 체계(플랫폼)로 발전시킨다.
최종 형태는 "읽는 문서"가 아니라 디자인 토큰·컴포넌트 규격·자동 검사(린트)로 실제 프로젝트에 바로 적용 가능한 것이어야 한다.
이 체계는 사람뿐 아니라 AI 코딩 에이전트가 읽고 그대로 적용하는 것을 전제로 한다.

## 진행 단계
1. 수집: 룰 후보를 모은다. 출처를 반드시 남긴다.
2. 정규화: 모든 룰을 정해진 형식으로 다시 쓴다. 중복은 합친다.
3. 충돌 해소: 룰 간 충돌을 찾아 우선순위 원칙에 따라 결정하고, 결정 이유를 기록한다.
4. 플랫폼화: 확정된 룰을 토큰 / 컴포넌트 규격 / 자동 검사 항목 / AI용 패키지로 변환한다.

## 카테고리
레이아웃(LAYOUT), 타이포그래피(TYPO), 색상·대비(COLOR), 간격(SPACE), 형태(SHAPE: 반경·그림자·엘리베이션·딤드),
내비게이션(NAV), 폼·입력(FORM), 피드백·상태(STATE: 로딩·에러·빈 화면), 접근성(A11Y), 반응형(RESP), 모션(MOTION),
문구·마이크로카피(COPY), 성능 체감(PERF), AI 기능(AI)
- AI 카테고리: 스트리밍·생성 중 상태, 중단·재생성·수정 경로, 출처·불확실성 표시, AI 오류와 "답 없음"의 구분, 사용자가 AI 결과를 검토·확정하는 흐름

목록의 정본은 `schema/categories.yaml` 이다. 새 카테고리가 필요하면 제안하되 임의로 늘리지 않는다.

## 충돌 시 우선순위
1. 법규·접근성 (WCAG 2.2, KWCAG 2.2)
2. 사용자의 과업 완료 (사용성)
3. 일관성 (체계 내부 규칙과의 정합)
4. 미적 선호

상위 원칙이 이기는 것이 기본이며, 다르게 판단한 경우 반드시 이유를 남긴다. 해소된 충돌은 결론을 룰에 명시한다.

## 출처 신뢰도
- 표준(WCAG, KWCAG, KRDS 등)과 검증된 연구를 우선한다.
- 유명 디자인 시스템(Material, Apple HIG 등)은 "참고 사례"로 취급하고 그대로 정답으로 삼지 않는다.
- 근거 없는 관행·취향은 "선호"로 표시해 표준 기반 룰과 구분한다.
- 수치나 출처가 불확실하면 지어내지 말고 "확인 필요"로 표시한다.

## 디자인 토큰
- 색·간격·타이포·반경·그림자·모션 값은 디자인 토큰(W3C DTCG JSON)으로만 정의한다.
- "토큰에 없는 값을 직접 쓰지 말 것"을 MUST 룰로 둔다.
- 토큰은 CSS 변수로 변환해 쓰는 것을 기본으로 한다.

## AI 적용
- 룰 문장은 AI가 오해할 여지가 없게 쓴다. "적절히", "충분히", "너무 많지 않게" 같은 표현은 수치나 조건으로 바꾼다.
- 산출물은 계층으로 만든다: ① 핵심 요약(MUST 중심, AGENTS.md / CLAUDE.md 분량 1~2쪽) ② 카테고리별 상세 파일 ③ ①②를 묶은 Claude 스킬 패키지.
- AI가 만든 결과물은 자동 검사기로 확인하고, 위반을 고치는 루프를 전제로 설계한다. AI의 "지켰다"는 자기 보고를 검증으로 간주하지 않는다.

## 한국어 웹 특수성
한국어 줄바꿈(word-break: keep-all 등), 한글 폰트와 행간·자간, 국내 접근성 기준(KWCAG), 공공 프로젝트용 디지털 정부 서비스 UI/UX 가이드라인(KRDS)을 별도로 고려한다.
