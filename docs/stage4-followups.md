# 4단계 후속 과제

컴포넌트 규격(components/)을 쓰면서 나온, 아직 룰·토큰으로 정하지 않은 것들. 결정하면 CF 또는 새 룰로 옮기고 여기서 지운다.

## 사람의 결정이 필요한 것
- (없음) — 스플래시 스크린은 CF-063으로 웹 범위 밖으로 결정했다(웹앱 첫 로드도 스켈레톤, PERF-018).

## 룰·토큰 후보
- **z-index 토큰 없음**: 언어 변경·화면 크기 조정 패널이 z-index 값을 직접 쓴다. 층(layer) 토큰(기본·드롭다운·고정 헤더·오버레이·모달·토스트)과 '토큰에 없는 z-index 금지' 룰 후보.
- **탭바 레이블 글자 크기**: TYPO-003(본문 16px 이상)이 내비게이션 레이블에 적용되는지 범위가 모호하다. tab-bar 규격은 KRDS 값(13px 상당)을 썼다.
- **탭바 하단 여백**: LAYOUT-001(초점 가림 방지)을 위해 본문 하단 여백을 고정 토큰으로 두었는데, 텍스트 확대로 탭바가 높아지면 스크립트로 맞춰야 한다.
- **사용자 피드백 수치 지침**: KRDS 사용자 피드백 패턴(선택지 2개, 별점 5개 이하, 추가 질문 3개 이하, 첫 질문 폐쇄형)에 대응하는 확정 룰이 없다(docs/stage2-followups.md 의 STATE 후보와 같음).
- **글자 수 표시의 보조기술 알림**: FORM-053은 표시 갱신만 정한다. text-area 규격은 aria-describedby 연결 + 최대 글자 수 도달 시 role=status 한 번 알림으로 정했다 — 룰로 올릴지 검토.
- **화면 크기 조정 키보드 방식**: KRDS 본문은 셀렉트형(닫힌 상태 ↑·↓), 규격은 디스클로저 + 라디오 묶음. KRDS 공공 프로젝트에서 어느 쪽을 표준으로 할지.
- **스낵바 자동 사라짐**: 작업 버튼이 있는 스낵바는 시간 제한이 생기지 않게 저절로 사라지지 않게 했다(A11Y-014). 업계 관행과 달라 CF로 남길지 검토.
- **긴급 공지 랜드마크**: KRDS 초안의 role="banner"는 main 안에서 쓸 수 없어 section + aria-label로 바꿨다(critical-alert kit_differences).
- **range-slider 대비**: 브라우저 기본 트랙에 의존한다. 트랙을 직접 그리면 실제 브라우저에서 COLOR-003(3:1)을 확인해야 한다.
- **KRDS 키트 색 조합**: 배지 disabled 변형·경고색 위 흰 글자는 4.5:1 미달이라 규격에서 뺐다(COLOR-002).
