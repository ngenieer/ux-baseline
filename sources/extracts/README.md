룰을 쓸 때 근거로 삼은 원문 데이터를 보관합니다. 손으로 고치지 않고 스크립트로 다시 만듭니다.

| 파일 | 내용 | 만드는 방법 |
|---|---|---|
| `WCAG22-A-AA.yaml` | WCAG 2.2 Level A·AA 성공기준 55개의 원문(규범 문장·Note), TR·Understanding 링크, axe-core 규칙 대응 | `scripts/extract_wcag.py` (사용법은 파일 머리말) |

## 수집 기록

### 2026-10-18 — A11Y 1차 (WCAG 2.2 A·AA + KWCAG 2.2)

- WCAG 2.2 A·AA 55개 → 룰 후보 55개. AAA 31개와 삭제된 4.1.1은 제외.
- KWCAG 2.2 검사항목 33개 중 30개는 WCAG 후보에 출처로 추가, WCAG에 대응이 없는 3개(5.4.4, 6.4.4, 8.1.1)는 별도 후보로 생성.
  KWCAG 대응은 비공식 HTML 판 기준이며 공식 원문 대조 전이다.
- 카테고리는 구현할 때 그 룰을 찾을 곳을 기준으로 배정했다. 예: 대비 → COLOR, 리플로우 → RESP, 폼 오류 → FORM.
  보조기술·마크업 의미 중심인 것은 A11Y.
- 모든 후보는 `stage: collected`, `needs_verification: true`. statement는 원문을 요약한 한국어 번역이다.
- 발견한 충돌 후보: `conflicts/BACKLOG.md`

### 2026-10-18 — KRDS 1차 (디자인 스타일 + 기본 패턴)

- 읽은 페이지: 디자인 스타일 8개(소개·색상·타이포그래피·형태·레이아웃·아이콘·엘리베이션·선명한 화면 모드),
  기본 패턴 11개(개인 식별 정보 입력·도움·동의·목록 탐색·사용자 피드백·상세 정보 확인·오류·입력폼·첨부파일·필터링·정렬·확인).
  아직 읽지 않은 것: 디자인 토큰 페이지, 컴포넌트 약 60개, 서비스 패턴 5종, 모바일 전용 패턴 2개, 가이드라인 PDF(2025-08 판) 원본.
- 사이트 본문은 요약 도구로 읽었다. 수치는 KRDS HTML Component Kit v1.1.0(github.com/KRDS-uiux/krds-uiux, 커밋 d6bb184)의
  토큰 파일·CSS와 대조했다. 그래서 모든 후보가 `needs_verification: true`이고, 원문 강도 표현(해야 한다/권장/바람직하다 등)을
  verification_note에 남겼다.
- 신규 후보 62개, 기존 후보 15개에 KRDS 출처 추가.
- 태그 `system-choice`: 보편적 UX 요구라기보다 KRDS라는 디자인 시스템의 고유 선택(브레이크포인트 값, 반경 공식 등).
  2단계에서 강도와 적용 범위(공공 전용인지)를 정한다. `public-sector`: 공공 서비스에만 해당.
- 카테고리가 없는 형태(반경)·엘리베이션·아이콘 항목은 ID 없이 `KRDS-uncategorized.md`에 보류.

### 2026-10-18 — KRDS 2차 (컴포넌트 56개 페이지)

- 컴포넌트 페이지 56개를 4개 묶음으로 나눠 읽고 규칙 초안 630개를 뽑았다(요약 모델 경유, 원문 대조 전).
- 처리 결과 (`KRDS-components.yaml`의 `outcome`):
  - 신규 후보 295개 — 태그 `krds-component`, `scope.level: component`
  - 기존 룰과 같은 요구 295개 — 새 ID 없이 대상 룰 70개에 KRDS 컴포넌트 출처를 1건씩 묶어 추가
  - 제외 40개 — 모바일 앱 전용(스플래시 등), 제작·운영 프로세스 지침, 기관 아이덴티티, 묶음 안 중복 통합
- 초안 630개 전체를 `KRDS-components.yaml`에 보존한다. 4단계 컴포넌트 규격(키보드 동작표, ARIA 속성)을 쓸 때 원자료로 쓴다.
- 발견한 충돌 후보 9건, KRDS 내부 불일치 5건 → `conflicts/BACKLOG.md`.
